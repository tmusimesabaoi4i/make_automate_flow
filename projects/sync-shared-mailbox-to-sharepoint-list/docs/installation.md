# インポート手順

対象: `flows/sync-mail-to-list/release/SyncSharedMailboxToSharePointList_20260803213000.zip`

> **重要**: 本パッケージは静的検証とオフラインテストのみを通過している。
> **実環境でのインポート・保存・実行は未実施**。以下の手順は設計上のものであり、
> 「この手順で成功することを確認済み」ではない。手順7と8は省略しないこと。

---

## 0. 事前準備

### 権限の確認

| 対象 | 必要な権限 |
|---|---|
| SharePointサイト | 参照権限。**新規作成する場合**はリスト作成と列・ビュー管理の権限（所有者/フルコントロール相当） |
| 共有メールボックス | Outlook接続を作るユーザーが対象メールボックスへアクセスできること（フルアクセス）。**書き込み権限は不要** |
| Power Automate | フローの作成・インポートができること |

### 接続の用意

インポート前に、次の3つの接続が作成済みだと割当がスムーズ。

- SharePoint
- Office 365 Outlook
- Content Conversion

【要実環境確認】Content Conversion が組織のDLPポリシーで許可されているか。
遮断されている場合、本フローは動作しない（代替は [troubleshooting.md](troubleshooting.md) 参照）。

### 入力値の用意

| 入力 | 例 |
|---|---|
| SharePointサイトまたはリスト一覧URL | `https://{tenant}.sharepoint.com/sites/{siteName}` |
| 作成するリスト名 | `メール台帳` |
| 共有メールボックスのアドレス | `shared-mailbox@{tenant}.example.com` |
| 取得件数 | `3`（初回は少なく） |

## 1. Power Automate を開く

https://make.powerautomate.com を開き、**対象の環境**が選ばれていることを確認する。

## 2. パッケージのインポート（レガシー）

左メニュー →「マイフロー」→ ツールバーの「インポート」→
「**パッケージのインポート（レガシー）**」を選ぶ。

> Dataverse の「ソリューション」からのインポートではない。本パッケージは
> レガシーパッケージ形式（ZIP内はJSONのみ・XMLなし）。

## 3. ZIPのアップロード

`SyncSharedMailboxToSharePointList_20260803213000.zip` を選択してアップロードする。
「パッケージのコンテンツを確認しています」の後、リソース一覧が表示される。

## 4. フローを「新規作成として」にする

「関連するリソース」一覧の**フロー**の行で「インポートのセットアップ」を開き、
**「新規作成として」**を選ぶ。既存フローの更新にしない。

フロー名は必要に応じて変更してよい（既定は `共有メールボックスのメールをSharePointリストへ同期`）。

## 5. 接続参照の割当

同じ一覧に**接続が3件**表示される。それぞれ「インポートのセットアップ」から
実際の接続を選択する。

| 表示名 | 選ぶ接続 |
|---|---|
| SharePoint への接続を選択してください | SharePoint |
| Office 365 Outlook への接続を選択してください | Office 365 Outlook |
| Content Conversion への接続を選択してください | Content Conversion |

パッケージ内の接続IDは匿名GUIDのため、**特定ユーザーの接続には固定されていない**。
一覧に該当の接続が出ない場合は、いったん別タブで「データ」→「接続」から接続を作成してから戻る。

## 6. インポートの実行

3件すべてに接続を割り当てると「インポート」ボタンが有効になる。実行する。

## 7. フローを開いて「すぐに保存」（**省略不可**）

インポート成功＝完成ではない。**インポートは通ったが保存で落ちる**種類のエラーが存在する
（自己参照・重複名・コネクタの必須パラメータ欠落など）。

1. 「マイフロー」からインポートしたフローを開く
2. **何も変更せずそのまま「保存」**する
3. エラーが出た場合は [troubleshooting.md](troubleshooting.md) の「インポート・保存時のエラー」へ

## 8. フローチェッカー

デザイナー上部の「**フローチェッカー**」を実行し、エラー・警告が0件であることを確認する。

## 9. 小規模テスト（新規リスト作成の確認）

1. 「テスト」→「手動」→ 実行
2. 入力: サイトURL / **まだ存在しないリスト名** / 共有メールボックス / **取得件数 3**
3. 実行後、最後の `Compose_Flow_Output` を開いて `status` が `Created` であることを確認
4. SharePoint 側でリストを開き、次を確認する
   - 列が5つ（メッセージID・日時・送信元アドレス・件名・本文）表示されている
   - 並び順が**日時の降順**（最新が上）になっている
   - 3件のアイテムが登録されている
   - 本文列に **HTMLタグがそのまま入っていない**

## 10. 再実行の確認（重複しないこと）

同じ入力でもう一度実行し、次を確認する。

- `status` が `Existing`
- アイテム数が**増えていない**
- `updatedCount` が 3、`createdCount` が 0

## 11. 段階的に件数を増やす

`3 → 10 → 50 → 100` の順で確認する。各段階で `fetchedCount` / `createdCount` /
`updatedCount` / `failedCount` を見て、失敗が出ていないことを確認してから次へ進む。

100件では SharePoint REST が約250回走る。Office 365 Outlook の調整制限
（300コール/60秒/接続）とフロー実行時間（目安30分）に注意する。

---

## 再インポート（更新）について

修正版を配布する場合は、**新しい日時付きZIPを追加**する（既存のリリースZIPは上書きしない）。
インポート時に「既存のフローを更新」を選ぶと接続の再割当が必要になることがあるため、
検証環境ではまず「新規作成として」で入れて比較するのが安全。
