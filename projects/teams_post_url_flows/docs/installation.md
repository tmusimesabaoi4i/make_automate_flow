# インポート手順書

対象ZIP:

- `flows/flow1-get-channel-post/release/Flow1_GetTeamsChannelPostFromUrl_20260724190952.zip`
- `flows/flow2-get-post-replies/release/Flow2_GetAllTeamsChannelPostRepliesFromUrl_20260724190952.zip`

2本は**それぞれ独立したフロー**です。片方だけインポートしても動作します。両方使う場合は同じ手順を2回行ってください。

---

## 重要な注意事項（必読）

1. **本パッケージは実環境でのインポートと実行に成功しています（2026-07-24・利用者報告）。** ただし確認されたのは「インポートでき、実行できた」という範囲で、返信51件超のページングや異常系の実挙動までは未確認です。ステップ7〜10はご自身の環境でも実施してください。
2. **レガシー形式のパッケージです。** インポートは「パッケージのインポート **(レガシー)**」から行います。「ソリューションのインポート」ではありません。
3. **Teams接続は、インポート作業を行うご自身のアカウントのものを選び直す必要があります。** ZIPには認証情報は一切含まれていません。
4. **インポート後は必ず一度「保存」してください。** インポートが成功しても、保存で初めて検出されるエラー（変数の自己参照・パラメータ検証など）があります。本パッケージは機械検証でこれらを0件にしていますが、実環境での保存確認はまだ行っていません。
5. **SharePointの事前準備は不要です。** 本フローはTeamsコネクタ1本のみを使い、リストもライブラリも使いません。インポート後にリスト・ライブラリを選び直す作業もありません。

## 0. 事前準備

### 0-1. 権限の確認

- 取得したい投稿があるTeamsチームの**メンバーであること**（またはチャネルメッセージの読み取り権限があること）
- Power Automate環境でフローをインポート・作成する権限があること

### 0-2. 対象URLの用意

Teamsで対象のチャネル投稿の「…」→「リンクをコピー」を実行し、URLを控えておきます。形式は次のようになります。

```text
https://teams.microsoft.com/l/message/19%3A....%40thread.tacv2/1706000000000?tenantId=...&groupId=...&parentMessageId=...
```

> チャットのURLは対象外です（`connector_requirements.md` §7）。

## 1. Power Automate を開く

1. ブラウザで `https://make.powerautomate.com` を開きます。
2. 組織アカウントでサインインします。
3. 画面右上の環境名を確認し、フローを作りたい環境が選ばれていることを確認します。違う場合は環境名をクリックして切り替えます。

## 2. 「マイフロー」→「インポート」→「パッケージのインポート (レガシー)」

1. 左側メニューの「マイフロー」をクリックします。
2. 上部の「インポート」ボタンをクリックします。
3. 選択肢から **「パッケージのインポート (レガシー)」** を選びます。

> 「ソリューションのインポート」ではありません。メニューの文言はテナントのバージョンによって多少異なります（「レガシーのインポート」等）。見当たらない場合は「インポート」ボタンの他の選択肢も確認してください。

## 3. ZIPをアップロードする

1. 「アップロード」欄をクリックし、対象のZIPを選びます。
2. アップロードが完了すると、パッケージの内容（フロー名と必要な接続）が表示されます。
   - Flow1: `Flow1_GetTeamsChannelPostFromUrl`（表示名「Flow1 Teams投稿URLから投稿を取得」）
   - Flow2: `Flow2_GetAllTeamsChannelPostRepliesFromUrl`（表示名「Flow2 Teams投稿URLから全返信を取得」）

## 4. 「インポートのセットアップ」でフローを「新規作成として」に設定する

1. フロー名の右側の操作列（「作成の種類」「インポート方法」等）をクリックします。
2. **「新規作成として (Create as new)」** を選びます。
3. 既存フローへの上書き（更新）は選ばないでください。

## 5. Teams接続を選択する（接続参照の設定）

パッケージが必要とする接続は **Microsoft Teams 1本だけ**です。

1. 「関連リソース」または「接続」の一覧に「Microsoft Teams への接続を選択してください」という行が表示されます。
2. 行をクリックし、ドロップダウンからご自身の既存のTeams接続を選びます。
3. 使える接続が無い場合は「新規作成」（+ アイコン）をクリックし、サインイン画面でご自身のアカウントで認証します。
4. 接続が正しく選択されると、行の左側にチェックマークが表示されます。

> **接続の中身について**: ZIP内では接続情報は匿名化されており（`connectionsMap.json` の値は実在しないGUID）、インポート時にここで選んだ実接続へ再マッピングされます。ZIPに認証情報は含まれていません。
>
> **要実環境確認**: 匿名化した接続GUIDが実接続へ確実に再マッピングされる挙動は、公式資料に明言が無く状況証拠のみです（`handbook/rules/07`）。もしインポート後にアクションが接続未設定の警告になった場合は、ステップ6で各Teamsアクションを開いて接続を選び直してください。

## 6. インポートを実行する

1. すべての接続行にチェックマークが付いていることを確認します。
2. 画面下部の「インポート」をクリックします。
3. 完了メッセージが出るまで待ちます。

> エラーが出た場合は `troubleshooting.md` を参照してください。

## 7. フローを開いて「すぐに保存」する（省略不可）

**この手順は省略しないでください。** インポート成功は保存できることを意味しません。

1. 「マイフロー」に戻り、追加されたフローをクリックします。
2. 「編集」をクリックしてデザイナーを開きます。
3. **何も変更せずに** 右上の「保存」をクリックします。
4. 保存に成功したら次へ進みます。エラーが出た場合はメッセージ（アクション名・エラーコード）を控えて `troubleshooting.md` を参照してください。

> **設定変更は不要です。** 本フローには環境固有の値（チームID・サイトURL・リスト名など）を保持している変数がありません。すべての識別子は実行時に入力URLから導出されます。したがって、インポート後に書き換えるべき変数はありません。

## 8. フローチェッカーを実行する

1. デザイナー右上の「フローチェッカー」をクリックします。
2. 「エラー」「警告」タブの内容を確認します。
3. エラーがあれば該当アクションを開いて確認します（`troubleshooting.md`）。

## 9. テスト実行する

1. デザイナー右上の「テスト」→「手動」→「テスト」をクリックします。
2. 入力フォームの **「Teams投稿URL」** に、0-2で控えたURLを貼り付けます。
3. 「実行」をクリックします。
4. 実行結果画面で各アクションが緑のチェックになっているか確認します。

確認したいポイント:

| アクション | 確認内容 |
|---|---|
| `Parse_ChannelId_From_Path` | 出力が `19:...@thread.tacv2` の形（`%3A` が復号されている） |
| `Parse_TeamId_From_Query` | 出力がチームのGUID |
| `Determine_TargetMessageId` | 出力が13桁の数値（親投稿のID） |
| `Validate_ParsedIdentifiers` | 出力が**空**（＝解析エラーなし） |
| `Get_Parent_Message` | 緑（成功）。出力の `body` にメッセージ本文が入っている |
| `Do_Until_Replies_Paging`（Flow2） | 反復回数が想定どおり。最後の `Set_ReplyNextLink` の出力が空文字 |
| `Serialize_Result_To_Json` | 出力（`varResultJson`）がJSON文字列になっている |
| `Compose_Flow_Output` | `success` が `true`、Flow2 は `replyCount` が実際の返信数と一致 |

> **`Scope_ErrorHandler` がスキップ表示になるのが正常です。** これは失敗時にのみ実行されるハンドラです。逆に `Scope_ErrorHandler` が実行されている場合は、前段のどこかが失敗しています。`Handle_Error` の出力の `error.code` / `error.details` を確認してください。

## 10. 段階的に確認する（Flow2）

Flow2 は返信件数によって実行時間が変わります。次の順で確認することを推奨します。

1. 返信が **0件** の投稿 → `replyCount: 0` / `replies: []` になるか
2. 返信が **数件** の投稿 → 件数が一致するか、本文が正しいか
3. 返信が **50件を超える**（複数ページになる）投稿 → `Do_Until_Replies_Paging` が2回以上反復し、`replyCount` が全件になるか

3が最も重要です。ここで件数が50で頭打ちになる場合はページングが機能していません（`troubleshooting.md`）。

## 再インポート（更新）について

同じフローを作り直す場合は、ステップ4で「新規作成として」ではなく既存フローの「更新」を選べます。ただし更新時は既存の設定が上書きされるため、手動で加えた変更がある場合は事前に控えてください。

`release/` 内の既存ZIPは上書きされません。ビルドし直した場合は新しい日時付きファイルが追加されるため、**最新のタイムスタンプのZIP**を使ってください。
