# インポートと初期設定の手順

対象: `TeamsChannelMemberSync_Setup`（フローA）と `TeamsChannelMemberSync_Daily`（フローB）。

---

## 0. 事前に用意するもの

| 用意するもの | 内容 |
|---|---|
| 管理サイト | 設定リストを置く SharePoint サイト。専用サイトでも既存サイトでもよい。**同期先サイトと別でよい**（別のほうが管理しやすい） |
| 同期先サイト | メンバー一覧を置く SharePoint サイト |
| TeamsチャネルURL | Teams のチャネルで「チャネルへのリンクを取得」して得られるURL |
| 接続アカウント | 対象チャネルのメンバーであり、上記2サイトで編集権限を持つアカウント |

リストは自動で作成されるので、事前に作る必要はない。

---

## 1. パッケージのインポート

フローA・フローBの順に、それぞれ次を行う。

1. Power Automate（`make.powerautomate.com`）で **マイフロー** を開く
2. **インポート → パッケージのインポート（レガシー）** を選ぶ
3. ZIP を選んでアップロードする
   - フローA: `flows/setup-and-test-sync/release/TeamsChannelMemberSync_Setup_<日時>.zip`
   - フローB: `flows/daily-member-sync/release/TeamsChannelMemberSync_Daily_<日時>.zip`
4. **確認が必要な項目** で、リソースごとに設定する
   - フロー本体: 「作成」（新規）を選び、必要なら名前を変える
   - Microsoft Teams への接続: 「インポート中に選択」→ 既存の接続を選ぶ、または作成する
   - SharePoint への接続: 同上
5. **インポート** を押す

> 【注意】レガシーパッケージのインポートには**サードパーティ Cookie の許可**が必要（公式）。ブラウザーがブロックしているとアップロード画面が進まない。

インポート直後、フローは**オフ**の状態で作成される。

---

## 2. 初回設定（フローAの手動実行）

**フローA はインポート直後にそのまま実行できる。事前の設定作業は要らない。**

1. フローA を開き、**テスト → 手動 → テスト** もしくは **実行** を押す
2. 入力する

   | 入力 | 必須 | 例・説明 |
   |---|---|---|
   | TeamsチャネルURL | ○ | Teams のチャネル名の「…」→「チャネルへのリンクを取得」で得られるURL。そのまま貼り付ける |
   | SharePointサイトURL | ○ | 同期先サイトのURL。一覧画面のURLでも可 |
   | SharePointリスト名 | ○ | メンバーを書き込むリストの表示名。存在しなければ作成される |
   | 他のチャネル設定を無効化する | — | 「はい」にすると、成功後に他のチャネルの設定を無効化して置き換える |
   | 設定リストを置くサイトのURL | — | **空でよい。** 空なら同期先サイトに設定リストを作る。複数チャネルの設定を1か所でまとめたいときだけ指定する |

3. 実行が終わったら、実行履歴で **`Scope_Finalize` → `Compose_Result_Summary`** を開く

確認する項目:

| 項目 | 期待値 |
|---|---|
| `success` | `true` |
| `configSaved` | `true` |
| `teamId` / `channelId` / `tenantId` | URL から取り出された識別子 |
| `siteUrl` | 正規化されたサイトルートURL |
| `listName` | 入力したリスト名 |
| `channelType` | `standard` / `private` / `shared` |
| `memberSource` | `connector`（ListMembers）または `graph`（フォールバック） |
| `memberCount` | Teams から取得したメンバー数 |
| `createdCount` / `updatedCount` / `unchangedCount` / `deactivatedCount` | 同期の内訳 |
| `errorCount` | `0` |
| `failedStage` | 空 |
| `adminSiteUrl` | 設定リストを作ったサイト。**この値を次の手順で使う** |
| `adminSiteSource` | `target-site`（同期先サイトへ作った）／`trigger-input`／`compose-admin-site` |
| `nextAction` | 次に何をすればよいかがそのまま書いてある |

`success` が `false` の場合は `failedStage` と `errorMessage` を見る（[troubleshooting.md](troubleshooting.md)）。
**テストが失敗した場合、設定リストには一切書き込まれない**ので、既存の正常な設定はそのまま残る。

4. `adminSiteUrl` のサイトに **「Teamsチャネルメンバー同期設定」** リストができ、1行追加されていることを確認する
5. 同期先サイトに指定した名前のリストができ、メンバーが並んでいることを確認する

---

## 3. 日次フローへ設定リストの場所を教える（1箇所だけ）

1. フローB を開き、**編集** に入る
2. 先頭付近の **`Compose_AdminSiteUrl`** アクションを開く
3. 「入力」に、手順2で確認した **`adminSiteUrl` の値をそのまま貼り付ける**
   （フローAの実行結果 `nextAction` にも同じ値が案内として出ている）
4. **保存** する

未設定のままフローB を実行すると、`ERR_ADMIN_SITE_NOT_SET` として安全に終了し、ここへ戻る案内が出る。

> **なぜこの1箇所だけ残っているか**: 日次フローは Recurrence トリガーなので入力を受け取れず、
> レガシーパッケージにはソリューションの環境変数のような「デプロイ時に値を与える仕組み」も無い。
> そのため「設定リストがどこにあるか」を実行時に知る手段が存在しない。
> フローA 側はこの制約が無いので、手作業なしで動くようにしてある。

---

## 4. 定期実行の有効化

1. フローB を開く
2. 右上の **オンにする** を押す

これで毎日 **07:00（日本時間）** に、設定リストの「有効」がオンの設定すべてについて同期が走る。

初回だけ手で動作を確かめたい場合は、フローB の **テスト → 手動 → テスト** で即時実行できる（Recurrence トリガーのフローも手動テスト実行できる）。

---

## 5. 別環境へ移すとき

本パッケージはレガシーパッケージ形式なので、Dataverse ソリューションのような環境変数・接続参照の入力画面は出ない。移送時の手順は次のとおり。

1. 移送先環境で §1 のインポートを行い、その環境の接続を選ぶ
2. §2 のフローA を移送先環境で実行し、設定を作り直す
   - 設定リストのアイテムはパッケージに含まれない。環境ごとに作り直す
3. §3 でフローB の `Compose_AdminSiteUrl` に、移送先環境での `adminSiteUrl` を設定する
4. §4 でフローB をオンにする

移送先で SharePoint のサイトURLやリスト名が変わる場合も、フローA を実行し直すだけでよい（フロー定義には一切埋め込まれていない）。

---

## 6. 複数チャネルを同期する

フローA を、チャネルごとに実行する（「他のチャネル設定を無効化する」は「いいえ」のまま）。設定リストに行が増え、フローB は有効な設定すべてを順に処理する。

**設定リストは1か所にまとめること。** 同期先サイトがチャネルごとに違う場合、既定（空欄）のままだとサイトごとに別々の設定リストができ、フローB は `Compose_AdminSiteUrl` が指す1か所しか見ない。2つ目以降のチャネルでは、フローA の「設定リストを置くサイトのURL」に**1つ目と同じサイト**を指定する（もしくは最初から全チャネルで同じ管理サイトを指定する）。

- 一時的に止めたい設定は、設定リストのその行の **有効** を「いいえ」にする。
- 同じチャネルに対してフローA を再実行すると、その行が更新される（`設定バージョン` が1つ進む）。行は増えない。
- 複数チャネルを同じリストへ同期することもできる（`チャネルID` 列で区別される）。ただしリストのアイテム総数が増えると毎回の取得件数が増える（[known_limitations.md](known_limitations.md) B-1）。

---

## 7. アンインストール

1. フローB をオフにする
2. 両フローを削除する
3. 設定リストとメンバーリストは**自動では消えない**。不要なら SharePoint から手動で削除する

フロー定義には削除系の REST が一切含まれていないため、フローを消してもリストのデータは残る。
