■ このフローについて
------------------------------------------------------------------------
表示名: PA_Save_Meeting_Attachment
推奨名(英語): PA_Save_Meeting_Attachment
ファイル名(本TXT): 05_save_attachment_child_flow.txt
フロー種別: 子フロー（呼出可能）。トリガーは「フローを手動でトリガーする」、
  末尾の「Respond to a PowerApp or flow」で戻り値を返す。
作成場所: [1]PA_Manual_Meeting_Archive_Start、[2]PA_Scheduled_Meeting_Archive_Start、
  [3]PA_Meeting_Archive_Orchestrator、[5]PA_Write_Run_Log と同一の
  Power Platformソリューション内。
役割: 添付ファイル1件を受け取り、(1)冪等性を台帳(MeetingArchiveLedger)で確認し、
  (2)未保存なら元ファイル本体を取得し、(3)ファイル名を yyyyMMdd_元名 に正規化して
  SharePointの保存先へ保存し、(4)保存後ファイルのURLを取得し、(5)台帳へ記録して、
  (6)結果を小さいJSONで親フローへ返す。1件の失敗で親を止めないため、失敗も
  戻り値(Status=Failed)として返す。
呼出元: PA_Meeting_Archive_Orchestrator（Apply_To_Each_Attachment内の
  Run_Child_Flow_Save_Attachment）。添付1件ごとに1回呼ばれる。
呼出先: なし（SharePoint標準アクションのみ使用）。

使用するコネクタ:
  - SharePoint（複数の項目の取得／ファイルコンテンツの取得(パス使用)／
    ファイルの作成／ファイルのプロパティの取得／項目の作成）
  - Power Apps（Respond to a PowerApp or flow）※子フローの戻り値用
  - 変数を初期化する／変数を設定する／作成(Compose)／条件／Scope は組み込み(built-in)
使用する接続:
  - SharePoint: 実行者のSharePoint接続。元ファイルのあるサイト（チームの
    SharePointサイト）への読み取り権限と、保存先サイト(envSiteUrl)への
    書き込み権限が必要。
必要な権限:
  - 元ファイルサイトの読み取り、保存先ライブラリ(envDestinationPath)への書き込み、
    処理台帳リスト(MeetingArchiveLedger)への読み書き。
プレミアムコネクタの有無: なし（SharePoint・Power Apps応答・組み込みは標準）。
管理者承認の必要性: 原則不要（標準コネクタのみ）。DLPでSharePointが制限される
  場合は要DLP確認。子フロー機能は要ライセンス確認。

Scope_Catch は Scope_Try の「失敗しました／タイムアウトしました」で実行。
Respond_To_Caller は Scope_Catch の後に置き、「構成 → 実行条件の構成」で
  Scope_Catch の「成功」「スキップ」「失敗」「タイムアウト」すべてにチェックを
  入れて“必ず実行”させる（Tryが成功→Catchはスキップ→Respond実行、
  Tryが失敗→Catch実行→Respond実行）。

  [21] Get_Source_File_Content（元ファイル本体の取得）
    コネクタ: SharePoint
    PA上のアクション名: ファイルコンテンツの取得（パス使用）
      （英語: Get file content using path）
    配置場所: [20]の次
    入力内容:
      サイトのアドレス: 元ファイルのあるサイト。多くの場合チームの

      ファイルパス: ContentUrlから解析したサーバー相対パス（%20等はデコード）。
    使用する式（ContentUrl解析の考え方。要実環境確認）:
      ・ContentUrlは https://テナント.sharepoint.com/sites/xxx/Shared%20Documents/...
        の形が多い。サイト部分（/sites/xxx まで）とサーバー相対パス部分に分ける。
      ・サーバー相対パス例:

        （uriPathはパス部分を返す。必要に応じ decodeUriComponent() で復号）

    次のアクション: Create_Attachment_File
    要SharePointコネクタ確認 / 要実環境確認:
      ・添付のcontentUrlはカード種別・共有リンク種別により形式が異なる。
        SharePoint上の実ファイルを指す場合のみ本アクションで取得できる。
      ・OneDrive上のファイルは「OneDrive for Business」の該当アクションを使う。
      ・Teams「Send a Microsoft Graph HTTP request」は許可セグメントが
        /teams・/me・/users・/chats に限られ /drives・/shares を呼べないため、
        ファイル本体取得には使えない（本アクションで取得する）。
      ・取得不能時は例外となりScope_Catchで捕捉し、Status=Failedで返す
        （1件失敗で親を止めない）。

■ 条件 / Apply to each / Do until / Select / Filter array / Compose / ページング
------------------------------------------------------------------------
条件: Condition_Already_Saved（既存保存の有無×強制再処理）、Condition_DryRun。
Apply to each: 使用しない（本フローは添付1件を処理する子フロー）。
Do until: 使用しない。
Select: 使用しない。
Filter array: 使用しない（絞り込みはSharePointのフィルタークエリで実施）。
Compose: IdempotencyKey/Extension/BaseName/Replace_Invalid_*/TrimTrailing/SavedName。
ページング: 使用しない（Get_Ledger_Existingは上限1件）。

■ 並列実行
------------------------------------------------------------------------
本フローはApply to each/Do untilを持たず、共通変数の競合は発生しない。
呼出元(オーケストレータ)側のApply_To_Each_Attachmentは並列オフ（初心者向け
主設計）。並列化する場合も本子フローは自己完結し共通変数を汚さない。

■ エラー処理
------------------------------------------------------------------------
Scope_Try/Scope_Catchで捕捉。1件の失敗で親を止めないため、失敗も
Status=Failedの戻り値として返す（例外を親へ伝播させない）。台帳へFailedを
記録して原因追跡を可能にする。ログにファイル本文・トークン・共有リンクの
認証情報を記録しない（正典§9）。

■ ログ
------------------------------------------------------------------------
台帳(MeetingArchiveLedger)への1行が本フローの主ログ。追加のエラーログが必要な
場合は、親(オーケストレータ)がまとめてPA_Write_Run_Logへ記録する方針
（本子フローからは呼ばず、戻り値ErrorMessageで親に伝える）。

■ 想定されるエラーと修正方法（正典§20書式）
------------------------------------------------------------------------
想定エラー: OriginalFileNameがnullでsubstring/splitが失敗
  原因: 添付にnameが無い。
  確認するアクション: Compose_Extension / Compose_BaseName
  確認する入力: triggerBody()?['OriginalFileName']
  修正方法: coalesce(...,'file')で既定名を与える（本設計では適用済み）。
  修正後の式: coalesce(triggerBody()?['OriginalFileName'],'file')

想定エラー: contentUrlがnull/空でファイル取得に失敗
  原因: 添付が実ファイルを指さない（カード等）。
  確認するアクション: Get_Source_File_Content
  確認する入力: triggerBody()?['ContentUrl']
  修正方法: 呼出元のFilter_File_AttachmentsでcontentUrl空を除外。到達時は
    Scope_Catchで捕捉しStatus=Failedを返す。
  修正後の式: 呼出元 @not(empty(item()?['contentUrl']))

想定エラー: MeetingDateがnull/空でformatDateTimeが失敗
  原因: 呼出元がMeetingDateを渡していない。
  確認するアクション: Compose_SavedName
  確認する入力: triggerBody()?['MeetingDate']
  修正方法: 呼出元(オーケストレータ)でCompose_MeetingDateを必ず渡す。防御的に
    既定値を与えるなら下式。
  修正後の式: formatDateTime(coalesce(triggerBody()?['MeetingDate'],
    formatDateTime(utcNow(),'yyyy-MM-dd')),'yyyyMMdd')

想定エラー: SharePointファイルが見つからない（Get_Source_File_Content）
  原因: パス解析誤り、権限不足、元ファイル移動/削除。
  確認するアクション: Get_Source_File_Content
  確認する入力: サイトのアドレス／ファイルパス
  修正方法: ContentUrlのサイト部・サーバー相対パスの分割を実データで確認
    （要実環境確認）。権限を付与。取得不能はStatus=Failedで継続。
  修正後の式: replace(uriPath(triggerBody()?['ContentUrl']),'%20',' ')

想定エラー: 同名ファイルが既に存在する
  原因: 過去実行の残存、または同一会議日・同名。
  確認するアクション: Create_Attachment_File
  確認する入力: ファイル名(Compose_SavedName)
  修正方法: 冪等キーで再保存自体を抑止（Condition_Already_Saved）。内容差異の
    同名は連番 _(2) 付与運用（要SharePointコネクタ確認）。

想定エラー: 保存先フォルダーが存在しない
  原因: envDestinationPathの誤り、フォルダー未作成。
  確認するアクション: Create_Attachment_File
  確認する入力: フォルダーのパス
  修正方法: 手順書10章で保存先フォルダーの存在を事前確認。envLibrary/
    envDestinationPathの綴りを確認。
  修正後の式: concat('/', <envLibrary>, '/', <envDestinationPath>)

想定エラー: ファイルへのリンク（保存後URL）を取得できない
  原因: Get_Saved_File_PropertiesのID指定誤り、{Link}未取得。
  確認するアクション: Get_Saved_File_Properties
  確認する入力: ID（Create_Attachment_FileのItemId）
  修正方法: 「Link to item」動的コンテンツを使用。取れない場合は{FullPath}
    からの構築式（スラッシュ非エンコード）。
  修正後の式: concat(<envSiteUrl>, replace(outputs('Get_Saved_File_Properties')?['body/{FullPath}'],' ','%20'))

想定エラー: coalesceの候補値の型が一致しない
  原因: 文字列既定''に配列/オブジェクトを混在。
  確認するアクション: 各coalesce
  確認する入力: 対象プロパティの型
  修正方法: 文字列は''、配列はjson('[]')、オブジェクトはjson('{}')を既定に。
  修正後の式: trim(coalesce(triggerBody()?['OriginalFileName'],''))

想定エラー: falseを未設定扱いしてDryRun/ForceReprocessを誤判定
  原因: coalesceでfalseをフォールバックしてしまう。
  確認するアクション: Condition_DryRun / Condition_Already_Saved
  確認する入力: triggerBody()?['DryRun'] / ['ForceReprocess']
  修正方法: equals(...,true)で厳密判定（本設計で適用済み）。
  修正後の式: equals(triggerBody()?['ForceReprocess'], true)

■ テスト手順
------------------------------------------------------------------------
1. 台帳リストを空にする。
2. 本子フローを単体テスト実行し、実在する添付1件分の入力
   （MessageId/AttachmentId/OriginalFileName/ContentUrl/MeetingDate=今日、
   DryRun=いいえ、ForceReprocess=いいえ）を渡す。
3. 保存先フォルダーに yyyyMMdd_元名 のファイルが1つできることを確認。
4. 戻り値Status=Saved、SavedFileUrlをブラウザで開くとそのファイルが開くこと。
5. 同じ入力で再実行→Status=Skipped、ファイルが増えないこと（冪等性）。
6. ForceReprocess=はいで再実行→再保存されること。
7. DryRun=はいで実行→Status=Skipped、ファイルが作られないこと。
8. 存在しないContentUrlで実行→Status=Failed、親が止まらないこと。

■ 完成条件
------------------------------------------------------------------------
・実ファイルが yyyyMMdd_元名 で保存先へ保存される。
・戻り値SavedFileUrlが保存後SharePointファイル自体を開くURLである。
・再実行で同一添付が無制限に複製されない（冪等キーで抑止）。
・1件失敗しても例外を親へ投げず、Status=Failedで返す。
・ログ/戻り値にファイル本文・トークン・認証情報を含めない。

■ 式・型検査結果
------------------------------------------------------------------------
・trim対象はすべて文字列（OriginalFileName等をcoalesce(...,'')で文字列保証）。
・coalesce候補は同一型（文字列は''、判定はequals(...,true)）。
・formatDateTimeはyyyy-MM-dd文字列に適用（MeetingDate）。null時の対処を明記。
・実在アクションのみ使用（複数の項目の取得／ファイルコンテンツの取得(パス使用)／
  ファイルの作成／ファイルのプロパティの取得／項目の作成／Respond to a PowerApp or flow）。
・実在WDL関数のみ使用（if/empty/trim/coalesce/concat/contains/split/last/
  substring/length/sub/greater/replace/endsWith/equals/first/uriPath/
  decodeUriComponent/utcNow/formatDateTime/string）。

========================================================================
式・型監査
========================================================================
trim対象はすべて文字列か:
  Yes。trimはtrim(coalesce(triggerBody()?['OriginalFileName'],''))等、文字列を
  coalesceで保証してから適用。配列/オブジェクト/Boolean/整数へは適用していない。
coalesceの候補値は同一型か:
  Yes。文字列プロパティは第2候補''で統一。ReplyId/OriginalFilename/ContentUrl等。
nullと空文字列を区別しているか:
  Yes。ReplyIdはempty(trim(coalesce(...,'')))で「null/空/空白」を判定し冪等キー
  の形を切替。空文字はフォールバックせず空のまま扱う箇所と区別。
空白だけの文字列を考慮しているか:
  Yes。Compose_IdempotencyKeyの分岐でtrim()後にemptyを判定。
配列の既定値がjson('[]')になっているか:
  該当する配列変数は本フローに無い（Get_Ledger_ExistingのvalueはSharePoint出力で
  常に配列）。length()で件数判定し、null前提の参照はしていない。
オブジェクトの既定値がjson('{}')になっているか:
  本フローでオブジェクト変数は使用しない（該当なし）。
falseを未設定扱いしていないか:
  Yes。DryRun/ForceReprocessはequals(...,true)で厳密判定し、coalesceで
  falseをフォールバックしていない。
0を未設定扱いしていないか:
  Yes。整数の未設定扱いは本フローに無い（件数はlength()で0以上を素直に判定）。
Apply to eachへnullを渡していないか:
  Apply to eachを使用しない（該当なし）。
JSONプロパティを安全に参照しているか:
  Yes。?['...'] とcoalesce/first併用。first(body('Get_Ledger_Existing')?['value'])
  はConditionで件数>0を確認した分岐内でのみ参照。
HTMLへ入れる値をエスケープしているか:
  本フローはHTMLを生成しない（該当なし）。HTML生成・エスケープは06セクション。
未定義の変数がないか:
  Yes。varStatus/varSavedName/varSavedFileUrl/varErrorMessage/varIdempotencyKey
  はフロー先頭で初期化済み。
未定義のアクション参照がないか:
  Yes。outputs()/body()参照はすべて先行アクション（Compose_*/Get_*/Create_*）を指す。
式内のアクション名が実在するか:
  Yes。Compose_IdempotencyKey/Compose_BaseName/Replace_Invalid_*/Compose_SavedName/
  Get_Source_File_Content/Create_Attachment_File/Get_Saved_File_Properties/
  Get_Ledger_Existing/Scope_Try は本TXTで定義したアクション名と一致。
添付リンクが保存後SharePointファイルを指しているか:
  Yes。SavedFileUrlはGet_Saved_File_Propertiesの「Link to item」（保存後ファイル
  自体を開くURL）。元Teamsリンク/元contentUrlは返さない。
会議が日付順に並ぶか:
  本フローの責務外（並べ替えはオーケストレータのGet_Sorted_Meetings）。本フローは
  会議日付をSavedNameの日付部にのみ使用。
各会議が新しいページから開始するか:
  本フローの責務外（改ページは06セクション）。該当なし。
