■ このファイルについて（最重要の前提）
------------------------------------------------------------------------
本ファイルは「独立した子フロー」の設計書ではありません。
ファイル名に含まれる "child_flow" は初期構想段階での名称の名残であり、
実際にはフロー [3] PA_Meeting_Archive_Orchestrator （中核・子フロー）の
Scope_Try 内、Get_Sorted_Meetings アクションの直後に配置される一連の
アクション（セクション）の詳細シートです。

00_overview.txt に明記の通り、最終的に作成するフローは5本のみであり、
本セクション専用の子フローは作成しません（06専用の「新しいフロー」画面は
開きません。フロー3の中に、以下のアクション群をそのまま追加します）。

本セクションが使用する変数 varDocumentHtml, varMeetingIndex は、
フロー3のトップレベルで既に初期化済み（正典§13: Initialize_DocumentHtml
＝文字列・既定値''、Initialize_MeetingIndex＝整数・既定値0）という前提で
記述します。本ファイル内で Initialize（変数の初期化）アクションは追加
しません。

本ファイルは、正典（CANONICAL_REFERENCE.md）§6・§7.7・§7.9・§7.10・§8を
根拠とし、名称・式は正典からそのままコピーしています。正典に明示のない
細部（後述「本シートで補う補助アクション」）のみ、正典の要求ロジックを
実現するために本シートで名称を補っています。

■ 7. 本シートで補う補助アクションについて（正典に無いが必要な名称）
------------------------------------------------------------------------
正典§6の「HTML生成(06)」アクション一覧には次の13個の名称のみが列挙され
ています：Set_DocumentHtml_Header, Apply_To_Each_Sorted_Meeting,
Escape_Ampersand, Escape_LessThan, Escape_GreaterThan, Escape_DoubleQuote,
Escape_SingleQuote, Compose_Body_With_Breaks, Compose_Page_Break,
Apply_To_Each_Saved_Attachment, Append_Attachment_Html, Append_Meeting_Html,
Increment_MeetingIndex, Append_DocumentHtml_Footer。

一方で、正典は次のロジックも明示的に要求しています（正典§7.10・§8、
および本タスク指示）：
  (a) 「varMeetingIndex>0のときだけ改ページを追加する」条件分岐
  (b) 「添付JSON配列が空のときは『添付ファイルなし』と表示する」分岐

このロジックを画面上で組むには、正典未記載の「条件」アクションと
「もう1つの追記アクション」が最低限必要です。本シートでは以下の4つを
補助アクションとして追加し、既存の正典アクション名（Compose_Page_Break,
Apply_To_Each_Saved_Attachment, Append_Attachment_Html 等）は一切変更・
改名していません。

| 補助アクション名             | アクション種類   | 根拠                                                   |
|-------------------------------|------------------|---------------------------------------------------------|
| Condition_Insert_Page_Break   | 条件             | 正典§7.10「2件目以降のみ改ページ」を実行するための分岐 |
| Append_Page_Break_Html        | 変数を設定する   | Condition_Insert_Page_Break の「はい」の場合にvarDocumentHtmlへ改ページHTMLを追記する |
| Condition_Has_Attachments     | 条件             | 正典§8「添付なし＝添付ファイルなし」を判定する分岐     |

※ 使用するアクション種類は、指示にある通り「SharePoint『ファイルの作成』
『ファイルのプロパティの取得』『複数の項目の取得』、変数を設定する、
作成(Compose)、Apply to each、条件」の範囲内に収めています。専用の

[1] Set_DocumentHtml_Header
------------------------------------------------------------------------
コネクタ            : 変数（組み込み）
PA上のアクション名   : 変数を設定する（Set variable）
配置                : Get_Sorted_Meetings の直後（Apply_To_Each_Sorted_Meetingの外側・前）
操作手順:
 1. 「+ 新しいステップ」をクリック
 2. 検索ボックスに「変数を設定する」と入力
 3. 「変数を設定する」を選択して追加
 4. アクション名を「Set_DocumentHtml_Header」に変更（「…」→名前の変更）
 5. 「名前」欄のドロップダウンで varDocumentHtml を選択
 6. 「値」欄に、下記のHTMLヘッダーをそのまま貼り付け（式ではなく直接
    テキストとして入力。改行を含めてよい）
入力: なし（varDocumentHtmlは初期値''のため、ここではconcatせず直接
        上書きで初期表示を作る）
値（そのままテキストとして貼り付け。正典§8のヘッダーと完全一致）:
```
<html><head><meta charset="utf-8"><style>
@page { size: A4; margin: 20mm; }
body { font-family: "Yu Gothic","Meiryo",sans-serif; font-size: 10.5pt; }
.page-break { page-break-before: always; }
.meeting-title { font-size: 16pt; font-weight: bold; }
.label { font-weight: bold; }
.attachment-list { margin-top: 8px; }
</style></head><body>
```
補足: 初回会議の前に改ページ（page-break）を入れないことで、Word/HTMLを
      開いたときに先頭に空白ページができるのを防ぐ（本タスクの明示要件）。
出力  : variables('varDocumentHtml') が上記ヘッダーで上書きされる
次のアクション: Apply_To_Each_Sorted_Meeting
実行条件（Run after）: Get_Sorted_Meetings が成功した場合
再試行        : 既定なし（変数操作のため再試行不要）
タイムアウト  : 既定
エラー時の処理: 通常失敗しない。万一失敗した場合はScope_Catchが捕捉

エラー時の処理: ループ内個別アクションの失敗はScope_Catchへ波及

■ 14. 並列実行に関する注意（varDocumentHtmlへの競合防止）
------------------------------------------------------------------------
Apply_To_Each_Sorted_Meeting と Apply_To_Each_Saved_Attachment は、
いずれも共通変数 varDocumentHtml へ「読み取り→concatで追記→書き戻し」
を行う。Power Automateの変数操作はスレッドセーフではないため、
同時実行度をオンにすると複数反復が同時にvariables('varDocumentHtml')を
読み取り、後勝ちの書き込みで一部の会議・添付の追記が失われる可能性が
ある。したがって両ループとも**同時実行度＝オフ（既定の逐次実行）**を
厳守する（正典§9）。varMeetingIndexの加算（Increment_MeetingIndex）も
同じ理由で逐次実行が前提。

■ 15. エラー処理
------------------------------------------------------------------------
本セクション全体はフロー3のScope_Try内にあるため、内部アクションの
失敗はScope_Catchで捕捉される（正典§9 Scope_Try/Scope_Catch/
Scope_Finally構成）。本セクション自体は外部コネクタを呼ばないため、
典型的な失敗要因は「参照先の値がnull/型不一致」「json()のパース失敗」
「配列添字エラー（dayOfWeek/json配列）」に限られる。1件の会議・1件の
添付でエラーが起きても、正典の設計思想（1ファイル失敗で全体停止しない）
に倣い、可能な限りCondition/coalesceで事前にガードする（本ファイルの
各Compose/Setで実施済み）。

■ 16. ログ
------------------------------------------------------------------------
本セクション自体はログ書き込み（Run_Child_Flow_Write_Run_Log_*）を
行わない。ログはフロー3のScope_Catch/Scope_Finallyから、会議件数
（varMeetingIndex）等をまとめて記録する（詳細は03/08セクション）。
本セクションの各アクションの入力・出力に、投稿本文の生データや
認証情報を含むログを別途出力しない（正典§9）。

■ 17. HTML肥大化対策（2年分データのボリューム対策）
------------------------------------------------------------------------
過去2年分の会議（想定数十〜百件超）を1つの文字列変数varDocumentHtmlに
逐次連結するため、以下のリスクと対策を明記する。
  - Power Automateの文字列変数・アクション入出力にはサイズ上限がある
    （フロー全体の実行ペイロードにも上限がある）。会議数・添付件数・
    本文の長さによってはvarDocumentHtmlが肥大化し、Create_Word_Archive_
    File（07セクション）でサイズ超過エラーとなる可能性がある
    （要実環境確認）。
  - 対策1（設計内で対応済み）: 1会議＝1ページで区切ることで、Wordを
    開いた後の閲覧性を保ちつつ、HTML自体の構造をシンプルに保つ。
  - 対策2（運用での回避策）: 初回は正典の推奨通りLookbackDays=7で
    小規模テストを行い、varDocumentHtmlの実サイズ・所要時間を確認して
    から730日（2年）の本番実行に進む（00_overview.txt「作成順序」参照）。
  - 対策3（要実環境確認・任意）: 2年分で実際にサイズ上限へ抵触する場合、
    HTMLを複数ファイルへ分割する（例: 四半期ごとに.docを分けて保存し、
    Word側で目視突合する）、またはStaging本文（BodyText）を要約・
    先頭N文字に短縮して1ページあたりの分量を抑える、のいずれかを
    追加検討する。ただし本文の改変は仕様書1.2「投稿本文の生成AIによる
    要約または内容改変は対象外」に抵触するため、要約による短縮は不採用
    とし、分割保存のみを代替候補とする。
