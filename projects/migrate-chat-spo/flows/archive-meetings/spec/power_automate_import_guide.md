# Power Automate インポート手順書（Teams課内会議アーカイブ）

対象フロー: `PA_Migrate_Teams_Meeting_Archive_To_SPO`（表示名: 「Teams課内会議アーカイブ」）
対象ファイル: `../release/PA_Migrate_Teams_Meeting_Archive_To_SPO_20260718012104.zip`
対象読者: Power Automateの操作に不慣れな方（画面操作が分かる粒度で記載）

この手順書は「ZIPをインポートしてから、テスト実行を経て本番運用に切り替えるまで」の作業だけを扱います。フローの内部設計・各アクションの意味は `power_automate_cloud_flow_implementation_guide.md`（同じspecフォルダー）（実装手順書）を参照してください。

## 重要な注意事項（必読）

作業を始める前に、必ず目を通してください。

1. **3つのコネクタ（Teams / SharePoint / Content Conversion）の接続は、インポート作業を行うご自身のアカウントのものを選び直す必要があります。** ZIPファイルには認証情報（サインイン情報）は一切含まれていません。インポート時に毎回、接続を選択（または新規作成）する画面が出ます。
2. **レガシー形式のパッケージです。** インポートは「パッケージのインポート **(レガシー)**」というメニューから行います。「ソリューション」からのインポートではありません。メニューを間違えると取り込めません。
3. **SharePoint関連のアクション（項目の取得・ファイルのプロパティ取得・ファイルの作成）は、ZIP内ではリスト名/ライブラリ名が仮の文字列として設定されています。** インポート後に、各アクションを開いて「サイトのアドレス」「リスト名」または「ライブラリ」を、お使いの実際のSharePointサイト・リストに選び直す必要があります（要実環境確認）。
4. **台帳・実行ログへの書込み4アクション（`Create_Ledger_Item`／`Create_Ledger_Item_Failed`／`Create_Run_Log`／`Create_Error_Log`）は、現行版でSharePoint「HTTP要求を送信します」(REST)方式に変わっており、「サイトのアドレス」欄が静的な選択値になっています。** 他のSharePointアクションのように変数を参照する式ではないため、**台帳・実行ログの作成先サイトが仮の値（`https://metijapan.sharepoint.com/teams/pjteam_220400119`）と異なる場合は、この4アクションを個別に開いて「サイトのアドレス」を実際のサイトに選び直す必要があります**（ステップ14参照）。この4アクションが参照するサイトは、添付ファイルの保存先サイト（`varSiteAddress`）とは**別物**（`varListSiteAddress`が指すサイト）である点に注意してください。リスト名（`varLedgerList`／`varRunLogList`）は引き続き変数化されているため、リスト名だけを変える場合は変数の変更のみで反映されます。
5. **事前にSharePoint側で `MeetingArchiveLedger`（処理台帳）と `MeetingArchiveRunLog`（実行ログ）の2つのリストを作成しておく必要があります。** 列の定義は本書の「0. 事前準備」、または実装手順書の12.4章・21章を参照してください。リストが存在しないと、フローチェッカーやテスト実行でエラーになります。**リストの列名は日本語などの非ASCII文字ではなく、ASCII英数字のまま作成してください**（非ASCII列名だとSharePointが生成する内部名がフロー内の式と一致しなくなります。詳細は0-1節）。
6. **この手順書に書かれているインポート手順のうち、v10（現行版）自体の実環境再実行はまだ行えていません。** 開発時の記録として、旧版（v3）のZIPは実環境での**インポート自体には成功**しましたが、その後の**保存**で変数の自己参照エラーが発生し、修正が必要でした。さらにその後、旧版（v6）のZIPはインポートには問題がなかったものの、保存時にSharePoint「項目の作成」(`PostItem`)の`item`パラメータが欠落するエラーが発生し、v7でこの4アクションをSharePoint REST方式に置き換えて修正しました。旧版（v8）のZIPは、実際に実環境でインポート・保存・実行のすべてに成功しましたが、実行時に添付取得アクション（`Get_Source_File_Content`）が404エラーで失敗し、v9でこれを修正しました。**そして旧版（v9）のZIPは、実際に実環境でエンドツーエンドの実行に成功しましたが、全ての添付ファイルが`Status=Failed`になるという事象が発生しました。** v10（現行版）はこの事象への対処（原因2候補への対応）です（本書末尾「実際に発生したエラーと対処」のエラー5参照）。v10はこれら5件の経緯を踏まえた修正を反映済みですが、**v10修正後の実環境再実行そのものは本プロジェクトではまだ検証できていません**（静的な機械検証のみ実施済みです）。インポート中やエラーが出た場合は、本書末尾の「トラブルシューティング」「実際に発生したエラーと対処」、および実装手順書のトラブルシューティング章（26章）を参照しながら手動で調整してください。
7. **`DryRun`（テスト実行）を「はい(Yes)」にしている間は、本番データへの保存（Word文書の本保存）を避けられます。** 動作確認が済むまでは、必ず `DryRun = はい` のまま実行してください。
8. **v10で初めて実行する前（特に旧v9パッケージを一度でも`DryRun=いいえ`で実行したことがある環境の場合）は、保存先フォルダーに前回実行の残骸ファイルが残っていないか確認してください。** v9の実環境実行では、添付ファイルの実体は保存先に作成できていたにもかかわらず処理が失敗として記録された可能性があり、その状態で同名ファイルへ再度保存しようとすると409相当のエラーになります（本書末尾「実際に発生したエラーと対処」のエラー5参照）。
9. **保存先フォルダーのパス（`varDestinationPath`）は`/`区切りで最大4階層までです。** v10で追加した保存先フォルダーの自動作成（`Scope_05_Ensure_Destination_Folder`）は先頭4階層までしか作成しません。5階層以上のパスにする場合は、5階層目以降を手動で作成しておいてください（実装手順書10.2節参照）。

## 0. 事前準備（インポート前に必ず実施）

### 0-1. SharePointリストの作成

**リストは `CreateMeetingArchiveLists` フロー（`../../provision-archive-lists/release/`配下の別パッケージ）で自動作成できます。** このフローをインポート・実行すると、2つのリストと列構成・既定ビューまで自動的に作成されます。以下の手順は、手動で作成する場合のものです（列構成は自動作成フローと同一にしてあります）。

作成先のSharePointサイトは、**保存先サイト（`varSiteAddress`）ではなく、`varListSiteAddress`が指すサイト**です。現行版では、台帳・実行ログの2リストをファイル保存先（`varSiteAddress`）とは別サイトに作成する設計になっています（詳細は実装手順書10.1節）。ステップ12で`varListSiteAddress`の値を確認してください。

**① MeetingArchiveLedger（処理台帳）**

| 列名 | 型（目安） |
|---|---|
| Title | 1行テキスト（既定列） |
| IdempotencyKey | 1行テキスト |
| RunId | 1行テキスト |
| MessageId | 1行テキスト |
| ReplyId | 1行テキスト |
| AttachmentId | 1行テキスト |
| OriginalFileName | 1行テキスト |
| SavedFileName | 1行テキスト |
| SavedFileUrl | **複数行テキスト（書式なし＝RichText FALSE）推奨（必須。「ハイパーリンクまたは画像」型は不可。理由は下記コラム参照）** |
| Status | 1行テキスト |
| ErrorMessage | **複数行テキスト（書式なし＝RichText FALSE）推奨** |
| ProcessedDateTimeUtc | 1行テキスト（または日付/時刻） |

**② MeetingArchiveRunLog（実行ログ）**

| 列名 | 型（目安） |
|---|---|
| Title | 1行テキスト（既定列） |
| RunId | 1行テキスト |
| FlowName | 1行テキスト |
| Level | 1行テキスト |
| ErrorMessage | **複数行テキスト（書式なし＝RichText FALSE）推奨** |
| MeetingCount | 数値 |
| SavedCount | 数値 |
| SkippedCount | 数値 |
| FailedCount | 数値 |
| ArchiveUrl | **複数行テキスト（書式なし＝RichText FALSE）推奨（必須。「ハイパーリンクまたは画像」型は不可。理由は下記コラム参照）** |
| Status | 1行テキスト |
| OccurredDateTimeUtc | 1行テキスト（または日付/時刻） |

> 詳細な列定義・作成手順は、実装手順書の「12.4 事前準備: SharePointリストの作成（処理台帳・実行ログ）」「21. エラー処理」に記載があります。列名・型で迷ったらそちらを確認してください。
>
> **列名はASCII英数字のまま作成してください（重要）**: 上記2つのリストの列名（`IdempotencyKey`、`SavedFileUrl`等）は、日本語などの非ASCII文字を使わず、そのままの英字で入力してください。SharePointは列作成時の名前をもとに内部名を決めますが、非ASCII文字を含む名前で作成すると内部名が`OData__x30d5__x30a1__x30a4__x30eb_`のようなUnicodeエスケープ形式になり、フロー内の式（列名をそのままキーとして参照する形）と一致しなくなります。これは実際に動作実績のあるサンプルフローの解析で確認された事象です。列の「表示名」を後から日本語に変更するのは問題ありません。
>
> **`SavedFileUrl`・`ArchiveUrl`・`ErrorMessage`は複数行テキスト（書式なし）で作成することを推奨します（重要）**: 現行版では、台帳・実行ログへの書込み（`Create_Ledger_Item`等4アクション）がSharePoint「HTTP要求を送信します」(REST)方式に変わっています。RESTで送信する本文は単純な文字列（URL文字列そのもの）であり、列を「ハイパーリンクまたは画像」型で作成していると、RESTが期待する`{"Url": "...", "Description": "..."}`という入れ子オブジェクトと形式が一致せず、書込みに失敗するおそれがあります。あわせて、SharePointの1行テキスト列は既定で255文字の上限があり、長いURL（クエリ文字列付きの共有リンク等）やエラー文言がこれを超えると切り捨てられる可能性があるため、`SavedFileUrl`・`ArchiveUrl`・`ErrorMessage`の3列は**複数行テキスト（詳細設定の「テキストの種類」を「書式なし（プレーンテキスト）」＝RichText FALSE）で作成することを推奨します**。1行テキストでも動作はしますが、切り捨てリスクがある点にご留意ください。いずれにせよハイパーリンク型・選択肢型は避けてください。

### 0-2. 事前に確認しておく情報

インポート後の設定変更で使うため、以下をあらかじめ手元に用意しておくとスムーズです。

- 対象のTeamsチーム・チャネル（Team ID・Channel IDを後で調べます）
- 保存先のSharePointサイトURL（`varSiteAddress`）、ドキュメントライブラリ名、保存先フォルダーのパス
- 台帳・実行ログリストの作成先SharePointサイトURL（`varListSiteAddress`）。**保存先サイトとは別サイトです**（実装手順書10.1節参照）。0-1で作成した2リストはこちらのサイトに置きます。
- 上記0-1で作成したリストの名前（既定のリスト名のままなら `MeetingArchiveLedger` / `MeetingArchiveRunLog`）。フロー内ではそれぞれ`varLedgerList`／`varRunLogList`という変数に設定します（ステップ14参照）。

### 0-3. 権限の確認

- 対象TeamsチームのメンバーまたはTeams/Graphの読み取り権限があること
- 保存先SharePointサイト（`varSiteAddress`）に書き込み（編集）権限があること
- 台帳・実行ログリストの作成先SharePointサイト（`varListSiteAddress`）に書き込み（編集）権限があること（保存先サイトとは別サイトのため個別に確認が必要です）
- Power Automate環境でフローを作成・インポートする権限があること

## インポート手順（全22ステップ）

### ステップ1: Power Automateを開く

1. ブラウザで `https://make.powerautomate.com` を開きます。
2. 組織アカウント（会社・組織のメールアドレス）でサインインします。
3. 画面右上の環境名を確認し、フローを作成したい環境（Environment）が選択されていることを確認します。違う場合は環境名をクリックして切り替えます。

### ステップ2: 「マイフロー」→「インポート」→「パッケージのインポート(レガシー)」を開く

1. 左側メニューから「マイフロー」をクリックします。
2. 画面上部（またはメニュー内）の「インポート」ボタンをクリックします。
3. 表示される選択肢の中から **「パッケージのインポート (レガシー)」** を選びます。

> 注意: 似た名前の「ソリューションのインポート」ではありません。今回のZIPはレガシー形式（`manifest.json` をルートに持つ形式）のため、必ず「パッケージのインポート (レガシー)」を選んでください。メニューの文言はテナントのバージョンによって多少前後する場合があります（例:「レガシーのインポート」等）。見当たらない場合は「インポート」ボタンの他の選択肢もあわせて確認してください。

### ステップ3: ZIPファイルを選択・アップロードする

1. 「パッケージの選択」または「アップロード」欄をクリックします。
2. ファイル選択ダイアログで `../release/PA_Migrate_Teams_Meeting_Archive_To_SPO_20260718012104.zip` を選択します。
3. 「開く」でアップロードを開始します。アップロードが完了すると、パッケージの内容（フロー名や必要な接続の一覧）が画面に表示されます。

### ステップ4: 「インポートのセットアップ」でフローを「新規作成として」に設定する

1. パッケージ内容の一覧に、フロー「Teams課内会議アーカイブ」（英語名: `PA_Migrate_Teams_Meeting_Archive_To_SPO`）が表示されます。
2. フロー名の右側にある操作列（「作成の種類」や「インポート方法」など）で、**「新規作成として (Create as new)」** を選択します。
3. 既存フローへの上書き（更新）は選ばないでください。初回インポートでは新規のフローとして作成します（内部的に新しいGUIDでフローが作成されます）。

### ステップ5: Teams接続を選択する（無ければ作成）

1. 同じ画面内の「関連リソース」または「接続」の一覧に、Microsoft Teamsコネクタの行が表示されます。
2. 接続欄のドロップダウンから、ご自身の既存のTeams接続を選択します。
3. 使える接続がない場合は「新規作成」（+ アイコン）をクリックし、サインイン画面でご自身のアカウントで認証してください。
4. 接続が正しく選択されると、行の左側にチェックマーク（緑色のアイコン）が表示されます。

> 注意: この接続はご自身のアカウントに紐づくものを新規に作る（または選ぶ）必要があります。ZIPには認証情報は含まれていません。

### ステップ6: SharePoint接続を選択する

1. 一覧内のSharePointコネクタの行で、ドロップダウンからご自身のSharePoint接続を選択します。
2. なければステップ5と同様に「新規作成」でサインインして接続を作成します。

### ステップ7: その他必要な接続（Content Conversion）を選択する

1. 一覧内の「Content Conversion」（HTMLをテキストに変換する機能で使用）の行についても、接続を選択します。
2. なければ新規作成します（多くの場合、組織アカウントでの認証のみで接続できます）。

### ステップ8: インポートを実行する

1. すべての接続行にチェックマークが付いている（未接続の項目がない）ことを確認します。
2. 画面下部の「インポート」ボタンをクリックします。
3. インポート処理が始まります。完了メッセージ、または「インポートが完了しました」といった通知が表示されるまで待ちます。

> 注意: 実際のテナントでこのインポートを行った実績はまだありません。エラーが表示された場合は、慌てずにエラーメッセージを確認し、本書末尾の「トラブルシューティング」を参照してください。

### ステップ9: インポートしたフローを開く

1. 左側メニューの「マイフロー」に戻ります。
2. 一覧に新しく追加された「Teams課内会議アーカイブ」を見つけてクリックします。
3. フローの詳細画面が開いたら、「編集」ボタンをクリックしてフローデザイナーを開きます。

### ステップ10: Team ID（varTeamId）を確認する

1. フローデザイナーの先頭付近にある「変数を初期化する」アクション群から、`varTeamId` を初期化しているアクションを探して開きます（初期値は仮のIDが入っています）。
2. 対象のTeamsチームの実際のTeam IDを確認します（Teamsアプリでチーム名の「…」→「チームへのリンクを取得」を開くと、URL内に `groupId=` の後ろにTeam IDが含まれています）。
3. `varTeamId` の値欄を、確認した実際のTeam IDに書き換えます。

### ステップ11: Channel ID（varChannelId）を確認する

1. 同様に `varChannelId` を初期化しているアクションを開きます（初期値は `19:...@thread.tacv2` の形式の仮の値です）。
2. 対象チャネルの「…」メニュー→「チャネルへのリンクを取得」からリンクを取得し、URL内の `19%3A...%40thread.tacv2` の部分（URLエンコードされています）を確認します。
3. デコードした値（`19:...@thread.tacv2` の形式）を `varChannelId` に設定します。

### ステップ12: SharePointサイト（varSiteAddress・varListSiteAddress）を確認する

現行版では、ファイル保存先とリスト操作先の**2つのサイト変数**があります。両方を確認・書き換えてください（実装手順書10.1節参照）。

1. `varSiteAddress` を初期化しているアクションを開きます（初期値は仮のサイトURLが入っています）。実際に添付ファイル・総括Word互換ファイルを保存したいSharePointサイトのURL（例: `https://（テナント名）.sharepoint.com/sites/（サイト名）`）に書き換えます。
2. `varListSiteAddress` を初期化しているアクションを開きます（初期値は仮のサイトURLが入っています。**この変数は現行版で新規追加されたものです**）。台帳（`MeetingArchiveLedger`）・実行ログ（`MeetingArchiveRunLog`）の2リストを実際に作成したSharePointサイトのURLに書き換えます。0-1で作成した2リストの場所と一致させてください。
3. `varSiteAddress`と`varListSiteAddress`は**同じサイトでも別サイトでも構いません**が、既定のZIPでは別サイト（ファイル保存＝mROOM、リスト操作＝pjteam）を想定した構成になっています。どちらの変数がどのアクションに対応するかは、ステップ14で詳しく確認します。

### ステップ13: 保存先フォルダー（varDestinationPath）を確認する

1. `varDestinationPath` を初期化しているアクションを開きます（初期値は仮のフォルダーパスが入っています）。
2. 実際にファイルを保存したいドキュメントライブラリ内のフォルダーパスに書き換えます。フォルダーが存在しない場合は、先にSharePoint上で作成しておいてください。

### ステップ14: 処理台帳リスト・実行ログリストを確認し、SharePoint系アクションでリスト/ライブラリ・サイトのアドレスを実物に再選択する

1. `varLedgerList` を初期化しているアクション（初期値 `MeetingArchiveLedger`）を開き、0-1で作成した処理台帳リストの名前と一致しているか確認します。名前を変えた場合はここも書き換えます。
2. `varRunLogList` を初期化しているアクション（初期値 `MeetingArchiveRunLog`）を開き、0-1で作成した実行ログリストの名前と一致しているか確認します（**この変数は現行版で新規追加されたものです**。旧版では`Create_Run_Log`・`Create_Error_Log`の「テーブル」欄に`MeetingArchiveRunLog`が直接ハードコードされ、変数化されていませんでした。現行版はこの1箇所を書き換えるだけでリスト名の変更が反映されます）。
3. フロー内のSharePoint関連アクション（「項目の取得」「ファイルのプロパティの取得」「ファイルの作成」など、複数箇所にあります）を **1つずつ開き**、以下を確認・選び直します。**アクションによって参照するサイト変数が異なる**ため注意してください（実装手順書10.1節・8.2節参照）。
   - `Get_Ledger_Existing`（処理台帳の項目取得アクション）: 「サイトのアドレス」はステップ12で設定した`varListSiteAddress`（台帳・実行ログの作成先サイト）を選択。「リスト名」は`MeetingArchiveLedger`を実物のリストとして選び直す。
   - `Create_Destination_Folder_L1`〜`L4`・`Verify_Destination_Folder`（保存先フォルダーの事前作成・検証アクション。**現行版で新設**）・`Create_Attachment_File`・`Create_Archive_Document`・`Get_Source_File_Content`（ファイル保存系アクション）: 「サイトのアドレス」はステップ12で設定した`varSiteAddress`（ファイル保存先サイト）を選択。**現行版では旧`Get_Saved_File_Properties`・`Get_Saved_Archive_Properties`（ファイルのプロパティの取得）は廃止されているため、これらのアクションは存在しません。**
   - 「ライブラリ名」: 会議アーカイブファイルを保存するドキュメントライブラリ（既定は「共有ドキュメント」など）を選び直す
4. **`Create_Ledger_Item`／`Create_Ledger_Item_Failed`／`Create_Run_Log`／`Create_Error_Log`の4アクション（台帳・実行ログへの書込み）は、現行版でSharePoint「HTTP要求を送信します」(REST)方式に変わっています。** これら4アクションには「テーブル」欄がなく、代わりに「サイトのアドレス」欄が**式ではなく静的な選択値**になっています。この4アクションを**個別に開き**、「サイトのアドレス」欄を実際の台帳・実行ログ作成先サイト（ステップ12の`varListSiteAddress`と同じサイト。**保存先サイト`varSiteAddress`とは別物**）に選び直してください。リスト名は「URI」欄の式が`varLedgerList`／`varRunLogList`変数を参照しているため、ステップ1・2の変数変更だけで自動的に反映されます（実装手順書8.3節・15.6節参照）。
5. すべてのSharePointアクションで、赤い警告アイコンが出ていないことを確認します。

> 注意: ZIP内ではこれらのアクションの「リスト」「ライブラリ」「サイトのアドレス」欄に仮の名前・値（文字列）だけが入っています。インポートしただけでは実際のリスト・サイトと紐付かないため、この作業は省略できません（要実環境確認）。
>
> **列名に関する注意（実働サンプルで実証済み）**: 0-1で作成するリストの列名は、日本語などの非ASCII文字ではなく**ASCII英数字のまま**にしてください。SharePointは非ASCIIの列名に対して`OData__x30d5__x30a1__x30a4__x30eb_`のようなUnicodeエスケープ形式の内部名を自動生成するため、フロー内の式（列名を直接キーとして参照する形）と一致しなくなり、書き込み・読み取りが失敗します。表示名を後から日本語に変更するのは問題ありません。

## 実際に発生したエラーと対処（開発時の記録）

本フローの開発過程で、実環境（または実環境相当の検証）で実際に遭遇した5件のエラー・事象と、その対処を記録します。現行版のZIPはこの5件とも対処済みですが、手動でフローを編集した場合に同種の問題が再発する可能性があるため、トラブル発生時の切り分けの参考にしてください。

### エラー1（旧版v2で発生・v3で修正済み）: インポート時の式パースエラー

- **症状**: パッケージのインポート時に、次のようなエラーで失敗しました。「電源フローのロジック アプリ フロー テンプレートが無効です。The template language expression 'if(contains(@coalesce(...' is not valid: the string character '@' at position '12' is not expected.」
- **原因**: フロー定義内の式の一部で、外側の`@if(...)`の内側にネストした`coalesce(...)`の前にも誤って`@`が付いていました。`@`は式文字列の先頭、または`@{...}`という補間の中でのみ有効で、ネストした関数の前に付けると不正な式になります。
- **対処**: 該当箇所から余分な`@`を除去。**現行版のZIPは修正済みで、この種のエラーは発生しないはずです。** もし同様のエラーメッセージが表示された場合は、手動で式を編集していないか確認してください。

### エラー2（旧版v3で発生・v4で修正済み・最重要）: 保存時のSetVariable自己参照エラー

- **症状**: ZIPの**インポート自体には成功**しましたが、インポート後にフローを**保存**しようとした時点で、次のエラーが発生しました。「フローの保存がコード 'WorkflowRunActionInputsInvalidProperty' およびメッセージ 'The inputs of workflow run action 'Set_MessagesArray' of type 'SetVariable' are not valid. Self reference is not supported when updating the value of variable 'varMessagesArray'.' で失敗しました。」
- **重要な教訓**: **「インポートに成功した」ことは「保存できる」ことを意味しません。** 本書のステップ15（フローを開いたら「すぐに保存」する）は、この種のエラーをできるだけ早期に発見するための手順です。
- **原因**: 「変数を設定する(SetVariable)」アクションの値の式が、更新対象の変数自身を参照していました（配列を`union(自分自身, 新しい値)`で累積しようとしていた）。Power Automateはこの自己参照を保存時に拒否します。
- **対処**: 自己参照していた3箇所を、いずれも「Apply to each」＋「配列変数に追加(Append to array variable)」の組み合わせに置き換えました。**現行版のZIPはこの修正を反映済み（機械検証済み・自己参照0件）ですが、実環境での保存確認そのものは行っていません。** ステップ15で必ず保存を試み、同様のエラーが出ないことを確認してください。

### エラー3（旧版v6で発生・v7で修正済み）: 保存時のPostItem「item欠落」エラー

- **症状**: 旧版（v6）のZIPは**インポート自体には問題ありません**でしたが、インポート後にフローを**保存**しようとした時点で、次のエラーが発生しました。「フローの保存がコード `OpenApiOperationParameterValidationFailed` およびメッセージ `Input parameter 'item' validation failed in workflow operation 'Create_Run_Log': The API operation 'PostItem' is missing required property 'item'.` で失敗しました。」
- **原因**: 台帳・実行ログへの書込みに使っていたSharePoint「項目の作成」(`PostItem`)は、必須の動的ボディ`item`（選択したリストの列スキーマから動的に生成されるフィールド群）を持ちます。本フローでは「リスト名」欄を`varLedgerList`・`varRunLogList`という**変数（式）**にしていたため、保存時の検証がリストの列スキーマを解決できず、`item`パラメータを組み立てられずに保存が失敗しました。保存時のエラー報告は1アクションずつしか行われないため`Create_Run_Log`だけが表示されましたが、同型の`PostItem`を使う4アクション（`Create_Ledger_Item`／`Create_Ledger_Item_Failed`／`Create_Run_Log`／`Create_Error_Log`）すべてが同じ理由で保存できない状態でした。
- **対処**: この4アクションを、SharePoint「HTTP要求を送信します」(REST)方式に置き換えました。「サイトのアドレス」は静的な選択値のまま、「リスト名」は`concat('_api/web/lists/getbytitle(''', variables('varLedgerListまたはvarRunLogList'), ''')/items')`というURIの式として引き続き変数参照できるようにしています。**現行版のZIPはこの修正を反映済み（機械検証済み・`PostItem`残存0件）です。** 詳細は実装手順書15.6章を参照してください。

### エラー4（旧版v8で発生・v9で修正済み）: 実行時のGet_Source_File_Content 404エラー

- **症状**: 旧版（v8）のZIPは、**インポート・保存・実行のすべてに成功**し、`MeetingArchiveRunLog`への書き込み（201応答、Id=1）まで到達しましたが、**実行時**に添付取得アクション（`Get_Source_File_Content`）が「404 File not found」で失敗しました（ユーザー提供の実行出力3ファイルで確認）。これは**インポート・保存の段階ではなく、実際にテスト実行した段階で発覚したエラー**である点が、エラー1〜3（いずれもインポート時または保存時のエラー）と異なります。
- **重要な教訓**: **「インポート・保存に成功した」ことは「実行時にすべてのアクションが成功する」ことを意味しません。** ステップ17（テスト実行）で各アクションの実行結果を1つずつ確認する作業（ステップ17の手順6）は、この種のエラーを早期に発見するために欠かせません。
- **原因**: 実際の添付`contentUrl`は`https://（チームのサイト）/Shared Documents/03_課内会議/…`のような形式で、Teamsチャネル添付の実体は**投稿元のチームのサイト**の`Shared Documents`配下にありました。旧版は`Get_Source_File_Content`の「サイトのアドレス」を`varSiteAddress`（添付・総括ファイルの**保存先**サイト。ステップ12参照）に固定し、「パス」にも`contentUrl`のサイト部分込みの値を渡していたため、「保存先サイトに対して、投稿元サイトのパスを問い合わせる」という食い違いが生じ、404になっていました。
- **対処**: `Get_Source_File_Content`の直前に`Compose_Source_Site`／`Compose_Source_Path`という2つの「作成(Compose)」アクションを追加し、`contentUrl`自体を`/Shared Documents/`の位置で前後に分割して、前半（サイトURL）・後半（サイト配下のパス）をそれぞれ「サイトのアドレス」「パス」として渡すよう変更しました。これにより`varSiteAddress`の設定値に関係なく、添付が実際に存在するサイトを毎回動的に特定できます。あわせて、`Filter_File_Attachments`の絞り込み条件にも`contentUrl`が`/Shared Documents/`を含むかどうかの判定を追加し、この形式に合致しない添付（外部リンク等）を候補の時点で除外するようにしました。詳細は実装手順書15.5節・14.3節・27.1節（v9）を参照してください。
- **現状**: v9のZIPはこの修正を反映済み（機械検証済み・0エラー0警告）で、**実際に実環境でエンドツーエンドの実行に成功しました**。しかし、その実行で次のエラー5が発生しました。

### エラー5（旧版v9で発生・v10で対処済み）: 添付ファイルの全件保存失敗

- **症状**: 旧版（v9）のZIPは、**実際に実環境でインポート・保存・実行のすべてに成功し、フローはエンドツーエンドで完走しました**（封じ込め・台帳への`Status=Failed`記録・エラーログの書き込みも正常に機能しました）。しかし、**添付ファイルが1件も保存されず、全件`Status=Failed`として記録されました**（例: ６Ｇと７Ｇ.pptx）。フロー自体は正常に最後まで動いたため、エラー1〜4のような赤い「×」表示や保存時エラーはなく、一見成功したように見えるが実際には添付が保存されていない、という気づきにくい事象です。
- **重要な教訓**: **フローが「エラー無く完走した」ことは「添付ファイルが実際に保存された」ことを意味しません。** ステップ22の手順4・5（`Verify_Destination_Folder`の確認、`MeetingArchiveLedger`の`Status`列の確認）を必ず行ってください。
- **原因（実行証跡の分析で判明。確度の高い順に2候補）**: 新しい実行証跡（Teamsチャネルの親投稿50件分のGraph応答）を分析したところ、失敗した添付の`contentUrl`自体は正しい形式（保存先とは別のチームのサイトの`Shared Documents`配下・非エンコードの生URL）であることが確認できました。つまり、エラー4で修正したサイト・パスの導出自体は正しく機能しており、**失敗の原因は保存側**にあると推定しました。
  1. SharePointの「ファイルの作成(CreateFile)」は、指定したフォルダーパスの中間フォルダーを自動作成しません。保存先フォルダー（`varDestinationPath`）は4階層のパスであり、そのいずれかが未作成だと全件が失敗します。
  2. （v9まで存在した）`Get_Saved_File_Properties`（ファイルのプロパティの取得）の「テーブル」欄に渡していた`Shared Documents`は、ドキュメントライブラリの**URLセグメント**であり、ライブラリの表示名やGUIDではありません。日本語のSharePointサイトでは既定ライブラリの表示名が「ドキュメント」であることが多く、名前解決に失敗して全件が失敗した可能性が**最有力候補**です。この場合、直前の`Create_Attachment_File`（ファイルの作成）自体は成功しており、**ファイルは実際に保存先へ作成できている**可能性が高い点に注意してください。
  また、新しい実行証跡から、Graphが添付`contentUrl`を%エンコード済み（`/Shared%20Documents/`）で返す場合があることも新たに判明し、既存の絞り込み条件がこの形式を想定していなかったための潜在バグ（候補に上らず黙って除外される）も見つかりました。
- **対処（v10・4本柱＋2件の堅牢化）**:
  1. フロー冒頭に`Scope_05_Ensure_Destination_Folder`を新設し、`DryRun=いいえ`の場合のみ保存先フォルダーを事前に作成・検証するようにしました（候補1への対処。実装手順書10.2節）。
  2. `Filter_File_Attachments`・`Compose_Source_Url`（新設）でエンコード済みURLにも対応しました（実装手順書14.3節・15.5節）。
  3. `Get_Saved_File_Properties`・`Get_Saved_Archive_Properties`（ファイルのプロパティの取得）を廃止し、保存後URLをCreateFileの成功事実から直接組み立てる方式に変更しました（候補2への対処。実装手順書16章）。
  4. 台帳の`ErrorMessage`列に、元の添付URLと保存先パスを自動的に記録するようにしました（自己診断化。実装手順書15.5節）。
  5. ファイル名のサニタイズに`#`・`%`の置換を追加しました（実装手順書15.3節）。
- **現状**: **現行版（v10）のZIPはこれらの対処を反映済み（機械検証済み・0エラー0警告）ですが、修正後の実環境での再実行はまだ行っていません。** ステップ22の本番実行で、`Verify_Destination_Folder`が緑色（成功）になっているか、また`MeetingArchiveLedger`に`Status=Saved`の行が記録され`SavedFileUrl`が実際に開けるかを必ず確認してください。もし再び`Status=Failed`が発生する場合は、`ErrorMessage`列の「元URL=／保存先=」の記載から原因を特定してください。**また、初回実行前には保存先フォルダーに前回（v9実行時）の残骸ファイルが残っていないか必ず確認してください**（候補2が正しければ、実際にはファイルが保存できていた可能性があるため。重要な注意事項8参照）。

## トラブルシューティング

インポート作業やテスト実行でうまくいかない場合は、以下を参照してください。

- **インポート自体が失敗する / 接続が反映されない**: 一度ブラウザを再読み込みし、パッケージの再アップロードから やり直してください。改善しない場合は、`power_automate_cloud_flow_implementation_guide.md`（同じspecフォルダー） の「26. トラブルシューティング」を参照してください。
- **フローの保存時にエラーが出る（特に自己参照・Self reference関連）**: 上記「実際に発生したエラーと対処」のエラー2を参照してください。
- **フローの保存時に`OpenApiOperationParameterValidationFailed`（`PostItem`の`item`欠落）エラーが出る**: 上記「実際に発生したエラーと対処」のエラー3を参照してください。現行版はこの4アクションをSharePoint REST方式に置き換え済みです。手動で`PostItem`に戻した場合は、サイト・リストの両方を静的値（式ではなくドロップダウン選択）にしてください。
- **SharePointアクションで赤い警告が消えない**: ステップ14の「サイトのアドレス」「リスト名」「ライブラリ」の選び直しが漏れていないか確認してください。
- **SharePointリストへの書き込みで値がずれる・想定した列に入らない**: リストの列名を非ASCII文字（日本語等）で作成していないか確認してください（0-1節・ステップ14の注意参照）。
- **（履歴・v10で解消）添付リンクが正しく表示されない（`{Link}` が空・エラー）**: v9までは`GetFileItem`の`{Link}`プロパティに依存していたため発生し得た症状です。**v10で`GetFileItem`自体を廃止し決定的URL構築へ変更**したため、`{Link}`関連のエラー自体が発生しなくなりました。リンクが正しく開けない場合はステップ19の注意事項（`varSiteAddress`／`varLibrary`／`varDestinationPath`の値の確認）を参照してください。
- **添付ファイルの本体が取得できない（`Get_Source_File_Content`が404 File not foundで失敗する）**: 上記「実際に発生したエラーと対処」のエラー4を参照してください。v9で`contentUrl`から動的にサイト・パスを導出する方式に修正し、v9のZIPは実際にエンドツーエンドで完走しました。それでも取得できない添付がある場合は、カードや共有リンクの形式が`/Shared Documents/`（またはそのエンコード形式）を含まない特殊な形式である可能性があります。実装手順書15章・14.3章を参照し、除外条件や取得方法を手動で調整してください。
- **添付ファイルが全件`Status=Failed`になる（フロー自体はエラー無く完走する）**: 上記「実際に発生したエラーと対処」のエラー5を参照してください。v10では保存先フォルダーの事前作成（`Scope_05`）と`GetFileItem`全廃で対処済みですが、修正後の実環境再実行はまだ確認できていません。`MeetingArchiveLedger`の`Status=Failed`行の`ErrorMessage`（元URL・保存先パスを記載）を確認し、原因を特定してください。
- **`Verify_Destination_Folder`が失敗し、フローがそこで停止する**: 保存先パス（`varSiteAddress`／`varLibrary`／`varDestinationPath`）が実在しない、または実行アカウントに編集権限が無い可能性があります。ステップ12・13で設定した値を再確認し、対象サイト・ライブラリ・フォルダーへの権限を確認してください（実装手順書10.2節参照）。また`varDestinationPath`が4階層を超えていないかも確認してください。
- **`Create_Attachment_File`／`Create_Archive_Document`が同名ファイルへの書込みでエラーになる（409相当）**: 前回実行の残骸ファイルが保存先に既に存在する可能性があります。保存先フォルダーを開いて確認し、不要なファイルを退避・削除してから再実行してください（重要な注意事項8・エラー5参照）。
- **`.doc` を開くとWordの形式警告が出る**: 想定内の挙動です（ステップ18の注意事項を参照）。気になる場合は拡張子を `.html` に変更する方法もあります。
- それでも解決しない場合は、実装手順書の「27. 制約と未確定事項」に記載の「要実環境確認」項目一覧とあわせて、該当箇所を手動で調整してください。
