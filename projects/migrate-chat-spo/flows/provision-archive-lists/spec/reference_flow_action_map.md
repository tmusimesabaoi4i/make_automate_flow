## Knowledge固有トークンの扱い（新フローでの残存確認）

以下のトークンは`../source/package`配下の全ファイルを対象に文字列検索し、**残存0件**であることを`../source/validate_list_definition.py`の`knowledge_tokens`検査で機械確認済み（`04_validation_report.md`参照）。

`tmplist` / `KnowledgeTag` / `KnowledgeTitle` / `KnowledgePrimaryTag` / `KnowledgeSummary` / `KnowledgeBody` / `varTagList*` / `getTagList` / `addRowPrimaryTag` / `filter*`（Knowledge系where句）/ `getInternalName*`（Knowledge系）/ `addViewField*`（Knowledge系）はいずれも**削除（サンプル固有）**であり、対応する構造パターン（列存在チェック→作成、表示名→InternalName解決→ビュー追加）のみを一般化して`Ledger`/`RunLog`向けに複製した。

| アクション | 判定 | 根拠 |
|---|---|---|
| `EnableAttachments` | 不採用（添付利用実績なし） | 単一フロー`../../archive-meetings/source/package/.../definition.json`および本リスト作成フローのいずれにも、台帳・実行ログリストへの添付ファイル付与処理が存在しない。添付ファイル自体はSharePointドキュメントライブラリへ直接保存され、リストアイテムへの添付という運用は行われていない |
