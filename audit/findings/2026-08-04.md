### 主要な不整合の詳細（修正前 → 問題点 → 修正後）

#### F-04 / F-05 / F-06 / F-08: Skill・Agent が2フローしか扱えなかった
**修正前**（`flow-error-fix` §2）:
> ルート `README.md` と `projects/migrate-chat-spo/` の構成から、対象フローとその `source/` を特定する。
> - archive-meetings → `flows/archive-meetings/source/build_package.py`。
> - provision-archive-lists → `flows/provision-archive-lists/source/build_list_package.py`。

**問題点**: 対象フローの候補が migrate-chat-spo の2本にハードコードされており、残り5フロー（teams 2本・create_initialized 1本・sync 2本）でエラーが起きてもSkillが対象を特定できない。同型全数検索も「**両フロー**」に限定されていたため、「もぐら叩き防止」という不変則5の目的自体が果たせない状態だった。

**修正後**:
> ルート `README.md` §3 の**フロー対応表**から、対象フローと `build_*.py` / `validate_*.py` を特定する。
> - 対象は `projects/<案件>/flows/<フロー>/source/`（全案件・全フローが対象。特定の案件に限定しない）。
> - どのフローか不明なら、エラーメッセージ中のアクション名を**全フローの `source/` に対してGrep**して絞り込む。

同型全数検索も「**全案件・全フロー**の definition と build_*.py を機械走査」に変更した。
**7フローの対応表は README §3 の1箇所だけに置き**、Skill側は参照させる形にした（表を6ファイルへ複製するとフロー追加時に更新漏れが起きるため）。

#### F-07: flow-release が同一ファイル内で矛盾していた
**修正前**: 「使う資材」では配置先を `projects/migrate-chat-spo/flows/<フロー>/release/` と書きながら、「命名・配置規則」では `projects/<案件>/flows/<フロー>/release/` と書いていた。
**問題点**: 同じSkill内で2通りの配置先が示され、migrate-chat-spo 以外のフローをリリースするときにどちらが正か判断できない。
**修正後**: 一般形 `projects/<案件>/flows/<フロー>/release/` に統一し、「命名・配置規則」節を正とする旨を明記した。

#### F-11: チェックリストが必須とする検査が7本中5本で未実装だった
**修正前**: `handbook/checklists/import_save_validation_checklist.md` §A は「その案件の validate_*.py が `tools/wdl_lint.py` を import している」ことを**必須項目**としていたが、実際に import していたのは sync 案件の2本のみ。
**問題点**: 文書が「必須」としているものが7本中5本で守られておらず、チェックリストが実態を保証していなかった。
**修正後**: 利用者の判断（2026-08-04）により**文書ではなく実装側を合わせた**。未対応の5本に共通リンターを組み込んだ。

```python
# 案件横断の共通リンター。どのフローにも当てはまる検査はここに集約してある
sys.path.insert(0, os.path.abspath(os.path.join(HERE, "..", "..", "..", "..", "..", "tools")))
from wdl_lint import lint_definition   # noqa: E402
...
for _msg in lint_definition(definition, raw):
    fail("[wdl_lint] " + _msg)
```

**retrofit の結果**: 全7フローの `validate_*.py` を実行し、**エラー0・警告0・`wdl_lint` の新規指摘0件**。
定義（`definition.json`）は一切変更していないため、`build_*.py` の修正・再生成・再パッケージは発生しなかった。
配線が実際に機能していることは、故意に自己参照を含む定義を通して L06 が検出されることで確認済み。

#### F-13: 実環境の確認状況が1バージョン古かった
**修正前**（`projects/migrate-chat-spo/README.md`）:
> v9（添付取得のクロスサイト404修正・添付有無分岐）は静的検証・式シミュレーションのみ。**実環境再実行は未実施**

**問題点**: 実際には v9 は実環境でエンドツーエンド実行に成功しており、そこで「添付が全件 `Status=Failed`」が発覚した（これが `error_catalog` のエラー7の出所）。現行版は既に **v10**。
案件READMEだけが v9 時点で止まっており、ルートREADMEとインポートガイド（どちらも v10 基準）と食い違っていた。**「未検証」と書くべき対象がずれている**ため、実行者がどのバージョンを検証すべきか判断できない。

**修正後**: 現行版が v10 であること、v9 で何が起きたか、v10 が未再実行であることを明示した。v10 の実環境再実行は **CONF-001** として登録した。
