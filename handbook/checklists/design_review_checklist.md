# 設計レビューチェックリスト

フロー設計時・レビュー時に確認する項目。機械的にチェックボックスで運用する。
詳細な根拠は[../knowledge/power_automate_tips.md](../knowledge/power_automate_tips.md)等を参照。関連ルール: [../rules/00_power_automate_core_rules.md](../rules/00_power_automate_core_rules.md)

## 全体構成
- [ ] 単一フローで完結するか、複数フロー分割が必要かを判断し、理由を記録した
- [ ] 複数フローに分割する場合、フロー間の変数受け渡し（子フロー呼び出しの入出力）の複雑度が許容範囲か確認した
- [ ] 標準コネクタのみで成立するか確認した（プレミアムコネクタ・カスタムコネクタ・汎用HTTP/HTTP with Entra IDが不要か）
- [ ] 管理者権限・Azure ADアプリ登録・管理者同意を前提とした実装になっていないか確認した

## 冪等性・安全性
- [ ] 同じ入力で複数回実行しても重複データが作られない設計（冪等キー等）になっているか確認した
- [ ] 破壊的操作（削除・上書き）は新規データ取得の成功後にのみ実行する順序になっているか確認した（取得前に全削除しない）
- [ ] 個別要素（添付1件等）の失敗が全体処理を停止させない設計になっているか確認した

## テスト容易性
- [ ] 小期間・少数データでテスト実行できるパラメータ（期間・件数の指定）が用意されているか確認した
- [ ] テスト実行（DryRun等）と本番実行を切り替えられるトリガー入力があるか確認した

## 大量データ・制限
- [ ] Do untilの終了条件と上限（count/timeout）が大量データ時にも安全か確認した
- [ ] フロー実行時間の上限（既定約30分）を超える可能性がある場合、期間分割等の対策を設計に含めた
- [ ] ページングが必要なAPI呼び出し（Graph等）にページング処理が実装されているか確認した

## 変数設計
- [ ] 更新不要な値はCompose、蓄積が必要な値のみ変数（Append/Increment）にしているか確認した
- [ ] 変数を更新するApply to each/Do untilの並列実行がオフになっているか確認した
