アクション定義テンプレート (Flow Action Definition Template)
====================================================================
1アクションにつき本ブロックを1つ使用する。実設計書TXTの書式を汎用化したもの。
関連ルール: rules/01_naming_conventions.md

[No.]
No.: （記入欄。実行順の通し番号）
アクション表示名: （記入欄。フロー全体で一意な名前）
内部名: （記入欄。表示名と異なる内部識別子がある場合のみ記入。無ければ「表示名と同一」）
コネクタ: （記入欄。例: Microsoft Teams / SharePoint / なし（制御アクション））
アクション種類: （記入欄。例: OpenApiConnection / SetVariable / AppendToArrayVariable /
  AppendToStringVariable / IncrementVariable / Compose / If / Foreach / Until / Scope）
配置するScope: （記入欄。ルート / 所属するScope名）
runAfter: （記入欄。先行アクション名と条件。例:{"先行アクション名":["Succeeded"]}。
  コンテナ起点のアクションは{}を明示する）
入力: （記入欄。主要パラメータとその値。動的コンテンツの参照元も書く）
式: （記入欄。Power Automate式。式が無い場合は「なし」）
出力型: （記入欄。string/array/object/boolean/integer等）
参照元: （記入欄。このアクションの入力が参照している先行アクション・変数）
参照先: （記入欄。このアクションの出力を参照している後続アクション・変数）
エラー処理: （記入欄。失敗時の扱い。個別catchの有無、再試行方針）
型検査: （記入欄。trim/coalesce対象の型が正しいか、自己参照が無いか等のチェック結果）

--------------------------------------------------------------------
記入ガイド:
- 「アクション種類」は表示名ではなくPower Automate内部のtype（例:SetVariable）で記入する。
  名前だけで判断すると「Append」という名前でも実体がSetVariableの場合を見逃す
  （knowledge/error_catalog.md参照）。
- 「型検査」欄はレビュー時にchecklists/expression_type_checklist.mdと照合して記入する。
